# 状态档案：模板与读写协议

状态档案是这个 skill 的心脏。**账在文件里，不在记忆里。** 对话会被压缩、会跨天、会开新窗口——任何依赖上下文记忆的守门都会失败。每次开口前先读档案，每次拿到新事实立刻写档案。

## 存放位置

```
~/.the-fool/<game-slug>/state.md     # 档案本体
~/.the-fool/<game-slug>/vault/       # 可选：已确认安全的当年材料落地
```

`<game-slug>` 用游戏名的小写拼音或英文短名（如 `bloodborne`、`xianjian1`）。

**`~` 必须解析成宿主真实的用户目录**，不要假设。不确定时先执行一次列目录确认路径存在。Windows 上 Git Bash 的 `~` 与原生 `%USERPROFILE%` 可能不同——以能实际读写成功的那个为准，并把绝对路径记进档案首行。

## 两条文件级原则

1. **文件防剧透。** 用户可能自己打开档案看。剧透内容绝对不能落盘——偷看自己的档案不能炸伤自己。
2. **挂账只记问题，不记答案。** 用户触线的问题，原文照抄（他自己问的，对他安全）+ 日期 + 解禁条件。答案不写。解禁时重新查证作答——多查一次的成本，换档案永远干净。

## 冷启动动序（每次对话的强制第一动作）

### 第一步：确定是哪个游戏

用户经常不说游戏名，只说"打到第三章了"。**不许猜。**

1. 列出 `~/.the-fool/` 下的所有档案目录。
2. 按结果分支：
   - **零个档案** → 没有进行中的游戏，按普通对话处理（除非用户正在开一个新游戏）
   - **一个档案** → 用它，并在回复里自然带出游戏名让用户能纠正："血源那边——打到哪了？"
   - **多个档案** → **必须问**："哪个？血源还是寂静岭？"不许按最近修改时间猜——用户完全可能回头去玩搁置的那个

### 第二步：读档案，失败即闭锁

读 `state.md`。

**"读不到"和"没有档案"是两件完全不同的事，绝不能混。**

- 列目录明确显示**没有这个游戏的文件夹** → 这是新游戏，走开局流程
- 文件夹存在但文件读不出来（权限、损坏、路径解析失败）→ **停下，告诉用户**：

  > 我读不到你的记录了（路径/权限问题）。在修好之前我不敢往下说——之前的约定我看不见。

  **绝不能**因为读取失败就当成新游戏、套用默认设置往下说。用户几周攒的约定会在一次静默失败里全部蒸发，而他不会知道。

- 写入失败同理：告诉用户，并声明本轮的新约定只在当前对话有效。

### 第三步：确认坐标

- **用户已经报了坐标**（"打到第三章了""打完了"）→ **不要再问**。直接接住，更新账本。
- **用户没报坐标** → 开放式问一句："打到哪了？"

判定依据是他这次说没说，**跟隔了多久无关**。间隔长短只影响另一件事：超过两周的回归，把档案里存的他上次的原话还给他。

### 第四步：查到期的账

扫解禁日历，有没有到期的。**到期的要还，但不抢在用户前面**——先接住他这轮说的内容，再问一句"要我把欠你的还了吗"。

## 写盘时机

- 用户报了新坐标 → 更新账本，**顺手记一句他当时的原话**（重启找情绪全靠它）
- 用户倒出新的已知 → 追加"他已经知道的"
- 触线问题挂账 / 埋了新种子 / 投放了装备 → 记入对应段
- 账还清了 → **立刻改状态标记**，不删除条目
- 用户立了新规矩或调整了线 → 更新约定，带日期
- 通关结算完成 → 按 settlement.md 归档

## memory 钩子（触发保险的第二层）

开局立约成功后，往用户级持久记忆写一条（用所在环境的 memory 机制；没有的话写进会被每次加载的用户级文件；都没有则跳过——档案本身仍是主保险）：

> 该用户有进行中的愚者档案：《游戏名》。任何涉及此游戏的对话，必须先读 ~/.the-fool/<slug>/state.md 再说话，剧透纪律以档案为准。

游戏归档后删除这条钩子。

## state.md 模板

```markdown
# 愚者档案：《游戏名》

档案绝对路径：<实际读写成功的完整路径>

## 约定
- 游戏：全名 / 平台 / 版本（原版还是重制、有没有用汉化补丁或模组）
- 首发年份：（决定有没有"当年"可回）
- 什么算打完：**以用户口径为准**。他说打完了就是打完了。
  你自己的判断可以记在这里备查，但不许拿它去驳用户
- 扮演视角：如"2015 年 3 月首发前玩家"；无历史可回则写"守门模式"
- 模式：悬置 / 鉴赏 / 乡愁 / 守门（内部用词，不出现在对话里）
- 剧透线：默认线（不主动透露任何剧情信息，见 what-to-block.md）

## 他调过的设置
<!-- 用户是主人。每一条改动原文照抄 + 日期。下次读出来照做，别让他说第二遍。 -->
<!-- 可调的不止剧透线：话多话少、要不要讲当年、要不要埋提示、要不要问进度、语气 -->
- [日期] 「用户原话」→ 永久 / 仅此一次

## 进度
- 最后坐标：用户的原话描述
- 确认时间：YYYY-MM-DD HH:MM
- 当时他说：一句原话（情绪快照，长时间搁置后重启时还给他）
- 历史坐标：
  - [日期] 坐标 ——「当时的话」

## 他已经知道的
<!-- 用户倒出的已知，原文照抄。不判断真假，不标注对错。 -->
<!-- 只在需要时加一句自己的备注：这条要格外小心 / 这条无所谓 -->
- [日期] 「用户原话」

## 欠他的
### 挂账（他问过、被挡下的问题）
- [待还] [日期] 「问题原文」→ 解禁条件：打完 / 打到某进度
- [已还 日期] [原挂账日期] 「问题原文」
### 藏品（超出当前进度的历史材料）
- [待还] 范畴描述（如"发售后的评测与读者反应"）→ 解禁条件
### 种子（已埋的注意力标记）
- [待发芽] [日期] 「种子原话」→ 预计位置（模糊描述，不剧透）
- [已回收 日期] 「种子原话」

## 已经给过的
<!-- 防止重复投喂 -->
- [日期] 投放内容简述
```

## 多游戏并行

一个游戏一个文件夹，约定互不污染。用户同时玩两个时各读各的档案；一个游戏里的解禁不影响另一个的线。**每轮对话开始时都要重新确认这轮说的是哪个游戏**，不要因为上一轮聊的是 A 就默认这一轮还是 A。
